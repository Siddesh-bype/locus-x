# LOCUS-X multi-floor positioning: delivery status

Date: 23 October 2026. Branch: `feat/multifloor-positioning` (local; not pushed, no pull request).

Documentation and HTTP-script fix: **`a644819`** — `fix(multifloor): correct the status numbers and assert finite floor probabilities`.
Every executable result below was produced by `a1fb985` except the live HTTP check in

This phase adds continuous 3-D ranging, inferred and route-assisted storey state, a
two-mode evaluation protocol, multi-floor API sessions and the matching frontend contract.
It does **not** validate real radios, calibrate floor probabilities, or infer a floor from
coplanar anchors on a single storey. The honest limits are listed in
[What is not implemented](#what-is-not-implemented).

Every benchmark number in this document was printed by a command shown in this document;
the [browser pass](#browser-pass--controller-verification) is the one section that reports
readings taken from the running UI, and it says so and quotes them. Raw
artifacts live under `artifacts/`, which is ignored by Git (`.gitignore:13`); they are
local-only and are regenerated by the commands in
[Artifacts and regeneration](#artifacts-and-regeneration). The printed tables below are
embedded verbatim because a reader of the repository cannot fetch a gitignored file.

## Multi-floor protocol runs

Both protocol files describe the same work (7 scenarios × 5 multi-floor routes × 2 seeds
× 240 steps = **16,800 frames** per run) and differ only in which mode they name as the
protocol identity. Each run evaluates both modes on one generated observation stream per
frame, so the two tables below score the same horizontal and vertical observations and the
same coverage inputs, differing only in floor evidence. Latency is an output, not an input:
it differs between the two modes within a single run, so it is not part of what the modes
share.

The runs were executed one at a time. Durations printed by the benchmark were **551.2 s**
and **644.6 s**. `results.json` contains no wall-clock field; the duration exists only on
stdout. `latency_ms` is the only nondeterministic field in the artifact.

Reading rules that the printed caveat enforces:

- The ranges, routes and slab attenuation are **synthetic**. These are not real-radio or
  calibration results and no deployment claim follows from them.
- **Floor accuracy counts a withheld storey as a miss, and its denominator is not the
  frame count.** `floor_accuracy` is 6,603 correct out of **11,970 frames that have a
  truth storey** (`floor_frames`), i.e. 0.552; the other 4,830 of the 16,800 frames are
  mid-traverse, where the route reports no truth storey and the metric is excluded
  (`multifloor/evaluation.py:98-99`). Ambiguity 0.561, by contrast, is over all 16,800
  frames. Of the 5,367 misses, roughly 4,590 are abstentions — frames whose `ambiguous`
  flag is set outside the excluded mid-traverse band — and 777 are frames where a storey
  was reported and was wrong. The per-scenario rows show the split; a single headline
  number invites the wrong reading.
- **Route-assisted transition success is freshness by construction.** The storey comes
  from the configured route, so `126/126` says the pipeline settles on the route's target
  floor within the tolerance window; it is not evidence of floor inference and must not be
  read as better than `80/126`. Route-assisted floor accuracy is `n/a` by construction.
- The identical horizontal/vertical errors across modes are expected: both localizers run
  the same 3D solve on the same ranges; only the floor decision differs.
- Transition counts depend on the 120 s horizon and the looping routes; a window whose
  `end + 5 s` is truncated by the horizon is dropped, so success rates are comparable only
  at equal horizons.
- Recovery is `0.000` everywhere because the mandated timed outage removes four anchors per

## What is not implemented

- **No real-radio or calibration claim.** Ranges, routes and slab attenuation are
  synthetic. The slab/NLOS model is a configured simulator term chosen to make storeys
  separable, not a measured propagation model. Nothing here validates UWB/BLE hardware,
  multipath, antenna behaviour or a real hospital.
- **Floor probabilities are likelihood scores, not calibrated posteriors.** They are
  exported as finite numbers and are used to decide a storey, but no calibration procedure
  or reliability diagram backs them. Coverage is an empirical synthetic-model figure, not
  a confidence guarantee.
- **Coplanar anchors on a single storey cannot name a floor.** If every anchor visible to
  the device lies on one storey, the vertical geometry does not separate that storey from
  its neighbours; this is a genuine geometric limitation, not a bug. Multi-floor
  observability requires anchors on more than one storey (or another vertical witness).
- **Inferred mode is legitimately ambiguous at t=0 and during vertical
  unobservability.** A cold start may not have enough vertical evidence, and a traverse
  can be vertically unobservable; the tracker then reports `floor_id: null` and
  `ambiguous: true` instead of guessing. The live check above observes exactly that at
  16 s into a traverse. Consumers must handle a null storey.
- **Route-assisted floor identity is configuration, not inference.** In that mode the
  storey follows the selected route; its floor accuracy is reported as `n/a` and its
  `126/126` transition success is freshness by construction, not floor detection.
- **Recovery is degenerate under the mandated fault matrix.** The timed outage removes
  four perimeter anchors per floor, leaving enough ranges that `updated` keeps firing; the
  measured recovery delay is therefore `0.000` everywhere. The metric and its tests exist,
  but this protocol demonstrates wiring, not recovery from a total blackout.
- **Not implemented at all:** real-radio validation, a trained reliability classifier,
  anchor-layout optimization (owned by the separate optimizer work), persistent storage,
  WebSocket streaming and deployment. No calibrated floor probability is claimed.
- **Aggregates are frame-weighted**, not route- or scenario-weighted; long dwell periods
  dominate a mode total. Per-scenario rows are the intended inspection surface.
- **Latency is machine- and load-dependent** and is the only field that does not
  reproduce between runs.

```powershell
& ".\.venv\Scripts\python.exe" -m backend.locus_x.benchmark --config configs/benchmarks/competition.json --output artifacts/multifloor-baseline/reference-reproduction
```

Regenerate everything, one at a time (the multi-floor runs take roughly 9–11 minutes each
on this machine and must not share one output directory):

```powershell
& ".\.venv\Scripts\python.exe" -m backend.locus_x.benchmark --config configs/benchmarks/competition.json --output artifacts/multifloor-verify/reference-reproduction
& ".\.venv\Scripts\python.exe" -m backend.locus_x.multifloor.benchmark --config configs/benchmarks/v3/multifloor-inferred.json --output artifacts/multifloor-benchmark-runs/inferred
& ".\.venv\Scripts\python.exe" -m backend.locus_x.multifloor.benchmark --config configs/benchmarks/v3/multifloor-route-assisted.json --output artifacts/multifloor-benchmark-runs/route-assisted
& ".\.venv\Scripts\python.exe" -m uvicorn backend.locus_x.main:app --host 127.0.0.1 --port 8021
& ".\.venv\Scripts\python.exe" scripts/verify_v3_http.py --url http://127.0.0.1:8021 --output artifacts/multifloor-verify/live-api.json
```

The benchmark refuses to reuse a directory that already contains `results.json` or
`metrics.csv`; choose a new `--output` or delete the old directory first. The
multi-floor artifact carries no wall-clock field, so a rerun with the same config and
seeds reproduces every stored value except `latency_ms`; run duration is printed to stdout
only.
